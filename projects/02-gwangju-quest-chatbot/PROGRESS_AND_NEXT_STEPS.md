## 3. 발견된 문제

### 3.1 긴 답변에서 채팅 스크롤이 불안정함

현재 `.chat-window`에는 다음 설정이 이미 있다.

```css
.chat-window {
  flex: 1;
  min-height: 0;
  overflow-y: auto;
}
```

그러나 상위 요소인 `.game-layout`과 `.chat-panel`에 `min-height: 0`, `height: 100%`, `overflow: hidden` 조합이 충분히 지정되지 않았다. CSS Grid 안의 Flex 컨테이너는 기본 최소 콘텐츠 높이 때문에 긴 AI 답변이 들어올 때 지정된 영역 안에서 줄어들지 않고 레이아웃을 밀어낼 수 있다.

또한 모바일 구간에서는 `.app-shell`이 `height: auto`로 바뀌고 `.chat-panel`에 `min-height: 610px`가 적용된다. 이때 내부 채팅창이 아니라 전체 페이지가 스크롤될 수 있어 사용자는 채팅 스크롤이 작동하지 않는 것으로 느낄 수 있다.

권장 수정:

```css
.game-layout {
  min-height: 0;
  overflow: hidden;
}

.chat-panel {
  height: 100%;
  min-height: 0;
  overflow: hidden;
}

.chat-window {
  overscroll-behavior: contain;
  scrollbar-gutter: stable;
}
```

모바일에서는 전체 페이지 스크롤과 채팅 내부 스크롤 중 하나를 명확하게 선택해야 한다. 앱 형태를 유지하려면 모바일에서도 화면 높이를 고정하고 채팅창만 스크롤하도록 구성하는 편이 자연스럽다.

수정 대상:

- `clients/style.css`
- 필요 시 `clients/script.js`의 자동 스크롤 처리

### 3.2 이전 대화 내용이 AI에 전달되지 않음

현재 브라우저는 `/chat` 요청마다 아래 정보만 전달한다.

- 현재 사용자가 방금 입력한 메시지
- RAG 사용 여부
- 플레이어, XP, Level, 완료 수, 현재 Quest

화면에 출력된 이전 사용자 메시지와 AI 답변은 서버로 보내지 않는다. 서버도 대화 세션을 저장하지 않는다. 따라서 다음과 같은 대화가 정상적으로 이어지기 어렵다.

```text
사용자: 친구랑 4시간 놀 거야.
AI: 어떤 여행 스타일을 좋아하세요?
사용자: 카페랑 사진.
```

두 번째 요청에서 AI가 받는 질문은 `카페랑 사진`뿐이다. 앞서 말한 `친구`, `4시간`, `광주 여행` 조건이 사라지므로 질문과 어긋난 답변이 나올 수 있다.

권장 수정:

1. 프론트엔드에 `conversationHistory` 배열을 둔다.
2. 사용자와 AI 메시지를 역할별로 저장한다.
3. `/chat` 요청에 최근 대화 기록을 함께 전송한다.
4. 서버 요청 모델에 `history` 필드를 추가한다.
5. 프롬프트에 이전 대화를 `HumanMessage`, `AIMessage` 형태로 포함한다.
6. 토큰 증가를 막기 위해 최근 8~12개 메시지만 전송하거나 요약한다.

수정 대상:

- `clients/script.js`
- `servers/main.py`
- `servers/prompt.py`

### 3.3 화면의 Quest와 AI가 말하는 Quest가 서로 독립적임

현재 좌측 Current Quest는 JavaScript에 미리 정의된 `quests` 배열에서 순서대로 표시된다. 반면 AI는 자연어 답변 안에서 별도의 Quest를 자유롭게 생성한다.

이 구조에서는 다음 문제가 생긴다.

- 화면은 `취향 탐색`인데 AI는 `ACC 아키텍처 포즈 챌린지`를 현재 Quest처럼 안내할 수 있다.
- Mission Complete 버튼은 화면의 고정 Quest만 완료한다.
- AI가 제안한 난이도와 XP가 실제 게임 상태에 반영되지 않는다.
- 사용자가 자연어로 완료를 말해도 화면 상태가 바뀌지 않는다.

권장 수정:

AI 응답을 구조화한다.

```json
{
  "response": "사용자에게 보여줄 메시지",
  "conversation_stage": "QUEST_ACTIVE",
  "quest": {
    "id": "acc-photo-01",
    "title": "ACC 포토 파트너",
    "description": "서로 사진을 한 장씩 찍어주세요.",
    "difficulty": "NORMAL",
    "xp": 100
  },
  "source": "gwangju_attractions.md"
}
```

프론트엔드는 이 `quest`를 좌측 패널에 표시하고, 완료 버튼은 해당 Quest의 XP만 반영해야 한다.

수정 대상:

- `servers/main.py`
- `servers/prompt.py`
- `clients/script.js`

### 3.4 대화 진행 단계가 명확하지 않음

현재 프롬프트에는 여행 조건 파악, 코스 추천, Quest 생성, 여행 종료 규칙이 함께 들어 있지만 어떤 단계인지 나타내는 상태가 없다. AI가 정보가 부족한데도 긴 코스를 만들거나, 사용자의 짧은 대답에 다시 처음 질문을 반복할 수 있다.

권장 대화 단계:

```text
COLLECTING_PROFILE
→ COURSE_PROPOSED
→ QUEST_ACTIVE
→ QUEST_RESULT
→ TRIP_SUMMARY
```

브라우저 또는 서버에서 현재 단계를 관리하고 AI에게 전달한다. `COLLECTING_PROFILE`에서는 한 번에 1~2개의 필요한 질문만 하고, 필수 조건이 모인 뒤에만 코스와 첫 Quest를 생성하도록 제한한다.

### 3.5 AI 답변이 너무 길어 사용성이 떨어짐

현재 모델은 한 번에 여러 코스와 Quest를 길게 제안할 수 있다. 긴 답변은 스크롤 문제를 악화시키고 현재 해야 할 행동을 흐리게 만든다.

권장 출력 규칙:

- 조건 확인 단계: 2~4문장
- 코스 제안: 장소 2~4개
- 현재 Quest: 한 번에 1개
- Quest 설명: 목표, 방법, XP를 합쳐 6줄 이내
- 다음 행동은 답변 마지막 한 줄에 표시
- 모델 최대 출력 토큰 설정

## 7. 수정 후 테스트 시나리오

### 연속 대화

```text
사용자: 친구랑 광주에서 4시간 놀 거야.
AI: 이동수단과 좋아하는 스타일을 질문한다.
사용자: 버스 타고 카페랑 사진 위주로 다닐래.
AI: 앞의 친구·4시간 조건을 유지한 코스를 제안한다.
```

확인 항목:

- `친구`, `4시간`, `버스`, `카페`, `사진` 조건이 모두 유지되는가
- 이미 답한 내용을 다시 묻지 않는가
- 현재 단계에 맞는 답변을 하는가

### 스크롤

1. 짧은 메시지 10개 이상 전송
2. 긴 AI 답변 수신
3. 마우스 휠, 터치패드, 스크롤바 드래그 확인
4. 최신 메시지 자동 스크롤 확인
5. 과거 메시지를 읽는 중 새 메시지가 왔을 때 강제 이동 여부 확인
6. 데스크톱과 모바일 너비에서 각각 확인

### Quest 동기화

1. AI가 생성한 Quest 제목과 좌측 카드가 같은지 확인
2. XP가 AI 응답의 보상과 일치하는지 확인
3. 완료 버튼을 두 번 눌러도 중복 XP가 지급되지 않는지 확인
4. 완료 후 AI가 다음 Quest를 한 개만 생성하는지 확인
5. `여행 끝` 입력 시 총 XP와 완료 수가 실제 화면 상태와 같은지 확인

## 8. 완료 기준

다음 조건을 모두 만족하면 Gwangju Quest 핵심 흐름이 완성된 것으로 본다.

- 긴 대화에서도 채팅 영역을 자유롭게 스크롤할 수 있다.
- AI가 최소 최근 대화 문맥과 여행 조건을 기억한다.
- 이미 답한 여행 조건을 불필요하게 반복 질문하지 않는다.
- AI가 안내한 현재 Quest와 화면 카드가 일치한다.
- Mission Complete가 정확한 XP를 한 번만 반영한다.
- 다음 Quest와 여행 종료 요약이 실제 게임 상태와 일치한다.
- RAG를 사용한 답변에는 출처가 표시된다.
- 네트워크, AI, 업로드 오류가 사용자 메시지로 표시된다.
- README와 실행 화면 캡처가 실제 최종 동작과 일치한다.

## 11. 2026-09-04 여행 프로필 및 AI Quest 동기화 완료

### 11.1 새 상태 구조

브라우저 `state`에 다음 상태를 추가했다.

- `travelProfile`: 플레이어, 인원, 관계, 시간, 이동수단, 취향, 걷기 선호, 날씨, 현재 지역
- `currentQuest`: 화면과 완료 로직이 함께 참조하는 단일 활성 Quest
- `completedQuests`: 완료 Quest의 id, 제목, 장소, XP 기록
- `secretQuests`: 일반 Quest와 분리한 플레이어별 비밀 Quest
- 기존 고정 Quest는 AI Quest가 없을 때만 사용하는 `fallbackQuests`로 축소

`TRIP PROFILE` 패널은 확인된 값만 표시하며, 새 정보가 들어와도 기존 값을 null이나 빈 배열로 덮어쓰지 않는다. 취향 배열은 중복 없이 누적한다.

### 11.2 `/chat` 호환 확장

기존 요청 필드 `message`, `use_rag`, `game_state`, `history`와 기존 응답 필드 `response`, `answer`, `source`, `rag_used`는 유지했다.

선택 요청 필드:

- `profile`: 현재 여행 프로필
- `completed_quests`: 최근 완료 Quest 목록

추가 응답 필드:

- `profile_updates`: 이번 발화에서 새로 확인한 여행 조건
- `quest`: 현재 활성화할 Quest 객체 또는 null
- `intent`: `NONE`, `QUEST_COMPLETE`, `TRIP_END`

### 11.3 구조화 응답 안정화

- 모델에게 JSON 객체 하나만 출력하도록 명시했다.
- 서버에서 Pydantic 모델로 프로필, Quest, intent를 검증한다.
- 명시적으로 말한 관계, 시간, 이동수단, 취향, 걷기, 날씨, 현재 지역은 서버 규칙으로도 추출해 JSON 품질에만 의존하지 않는다.
- JSON 전체 검증이 실패하면 유효한 응답 텍스트와 각 하위 필드를 부분적으로 복구한다.
- 모델이 답변에 Quest를 설명하면서 `quest` 필드를 null로 둔 경우, Quest 제목·수행법·난이도·XP·장소를 답변에서 복구한다.
- 최종 파싱이 실패해도 기존 텍스트 응답은 정상 반환해 `/chat` 500 오류를 방지한다.

### 11.4 Quest 동기화와 완료

- AI 응답의 `quest`가 있으면 `state.currentQuest`로 저장하고 왼쪽 카드가 같은 객체를 표시한다.
- 카드에는 Quest 제목, 설명, 장소, 난이도, XP를 표시한다.
- 완료 버튼은 현재 활성 Quest만 완료하고 XP와 완료 수를 갱신한다.
- 완료된 Quest id를 기록하고 버튼을 비활성화해 재클릭 XP 중복 지급을 막는다.
- `QUEST_COMPLETE` intent는 버튼 클릭과 동일한 함수를 호출한다.
- 완료 후 `currentQuest`를 비우고 `다음 미션 줘` 요청에 프로필과 완료 목록을 함께 보낸다.
- 완료한 Quest와 제목·장소·수행 방식이 같은 미션은 반복하지 않도록 프롬프트와 브라우저 양쪽에서 방어한다.
