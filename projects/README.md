# 관통 프로젝트 관리 가이드

모든 관통 프로젝트를 이 저장소 안에서 차수별로 보관합니다. 프로젝트가 10차 이상 누적돼도 같은 위치에서 같은 종류의 문서를 찾을 수 있도록 아래 규칙을 사용합니다.

## 폴더 이름

```text
차수-프로젝트명
```

예시:

```text
01-enjoytrip-java
02-gwangju-quest-chatbot
03-enjoytrip-database
04-enjoytrip-spring
```

차수는 정렬이 흐트러지지 않도록 항상 두 자리 숫자로 작성합니다. 각 폴더는 다른 차수에 의존하지 않고 실행할 수 있는 독립된 제출 단위로 관리합니다.

## 권장 폴더 구조

```text
NN-project-name/
├─ README.md              # 개요, 실행 방법, 주요 기능과 화면
├─ src/ 또는 clients/     # 구현 소스
├─ servers/               # 서버가 있는 경우
├─ screenshots/           # 실제 실행 화면
├─ docs/                  # 추가 설계·고찰 문서가 있는 경우
└─ .gitignore
```

프로젝트 특성에 따라 폴더 이름은 달라질 수 있지만 최소한 다음 자료를 포함합니다.

- 구현 소스 코드
- 실행 방법과 주요 기능을 기록한 `README.md`
- 실제 실행 화면
- 과제에서 요구한 고찰·평가 문서

API 키와 개인 인증 정보, `.env`, 가상환경, 빌드 결과와 로컬 데이터베이스는 포함하지 않습니다.

## 차수 완료 체크리스트

- [ ] `projects/NN-project-name/` 안에서 독립 실행 가능
- [ ] 프로젝트 README에 실행 환경과 명령어 작성
- [ ] 핵심 기능과 담당 역할 작성
- [ ] 실제 실행 화면과 이미지 설명 추가
- [ ] 요구사항·고찰·성능평가 문서 포함
- [ ] 비밀키, 토큰과 개인 경로가 없는지 확인
- [ ] 메인 README의 현황·기술 확장 표 갱신
- [ ] `project-NN-YYYYMMDD` 완료 태그 생성

다음 프로젝트는 [`_template/README.md`](_template/README.md)를 복사해 시작합니다.
