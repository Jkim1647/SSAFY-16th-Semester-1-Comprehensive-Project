# 통합 게시판 기능 및 검증 기록

작성일: 2026-10-30 · 브랜치: `codex/board-community`

## 적용 범위

게시판의 높음·보통 우선순위 기능과 공지 고정 관리를 구현했다. Servlet/JSP/JDBC 구조를 유지하며 기존 공지·일반 게시글의 ID와 본문, 작성자, 권한은 보존한다. 상단의 공지사항·자유게시판 메뉴는 **게시판** 하나로 통합했다.

| 기능 | 사용 방법·정책 |
|---|---|
| 통합 게시판 | `/board`에서 공지와 일반 글을 함께 조회. 기존 `type=notice/free` 링크는 같은 게시판의 유형 필터로 동작 |
| 글 유형·분류 | 일반 회원은 일반 글, 관리자는 공지 또는 일반 글 작성. 일반·여행 후기·충전 팁·질문·동행 모집 분류 |
| 검색·정렬 | 제목/내용/작성자 검색, 최신순·조회순·좋아요순. 페이지당 10건. 목록 조건은 상세·작성·수정·삭제 왕복 시 유지 |
| 좋아요 | 로그인 회원이 글당 1건 등록/취소, 개수와 내 선택 표시. 자기 글·공지에도 허용 |
| 북마크 | 로그인 회원이 등록/해제. 내 목록은 본인만 조회. 기본 저장일 내림차순 |
| 댓글 | 로그인 작성, 본인 또는 관리자 수정/삭제. 페이지당 20건. 새 댓글 등록 시 해당 페이지와 댓글 위치로 이동 |
| 내 활동 | 내 글·내 댓글·좋아요한 글·북마크를 게시판에서 전환. 헤더의 회원 메뉴·마이페이지에 진입 링크 |
| 신고 | 글·댓글 신고, 사유 필수. 같은 회원·대상은 한 건. 관리자는 신고 관리에서 확인하고 처리 사유 기록 |
| 숨김·복구 | 관리자만 사유와 함께 처리. 숨긴 글·댓글은 일반 이용자 조회·검색·반응·개인 활동에서 제외. 관리자는 게시판에서 확인·복구 가능 |
| 공지 고정 | 관리자 공지 상세에서 설정. 순서 0~999(작을수록 먼저), 시작/종료 선택. 한국 시간 기준 시작 포함·종료 미포함 |
| 관리 기록 | 공지 고정 변경, 글·댓글 숨김·복구의 관리자·사유 기록. 해당 글 상세에서 최근 50건 확인 |

고정 공지는 검색·유형·분류·내 활동 필터가 없는 전체 목록의 첫 페이지에서 별도 노출한다. 일반 목록과 중복되지 않으며 고정된 공지도 검색·유형 필터에서는 일반 검색 결과로 조회할 수 있다. 기존 공지는 데이터를 바꾸지 않으므로 자동 고정되지 않는다. 관리자가 필요한 공지를 고정하면 된다.

내 댓글 목록에서는 숨긴 댓글·글을 제외한다. 링크의 댓글 페이지는 관리자와 일반 회원이 상세에서 실제로 볼 수 있는 댓글 범위에 맞춰 계산한다.

이미지 첨부·알림·대댓글은 이번 범위에 포함하지 않았다.

## 구조와 기존 데이터 호환

- `BoardController`와 기존 board JSP를 확장했다. 기존 `BoardService`의 권한 규칙과 조회수 처리를 재사용한다.
- `BoardCommunityService`가 확장 기능의 정책·트랜잭션을 담당하며 `BoardCommunityDao` 인터페이스와 `JdbcBoardCommunityDao`가 JDBC 저장·조회를 담당한다.
- `45-board-community.sql`은 추가 테이블만 만든다. 기존 boards 컬럼 ALTER, 기존 행 UPDATE/DELETE, 공지 유형 변환을 하지 않는다.
- 추가 테이블: board_settings, board_likes, board_bookmarks, board_comments, board_reports, board_moderation.
- 설정 행이 없는 예전 게시글은 LEFT JOIN 기본값으로 일반 분류·공개 상태로 읽는다.
- `AppInitListener`의 스키마 목록에 새 SQL을 등록했다. 새 빌드를 배포하고 앱을 재시작하면 `CREATE TABLE IF NOT EXISTS`로 생성한다. 새 파일을 폴더에 두는 것만으로는 현재 실행 중인 서버에 적용되지 않는다.
- 게시글·회원 삭제는 기존 물리 삭제를 유지하며 추가 관계는 FK CASCADE로 정리한다. 작성자가 탈퇴하면 그 글을 저장한 다른 회원의 북마크도 삭제된다.

## 비기능 요구사항 반영

| 항목 | 적용 내용 |
|---|---|
| 중복·재시도 | 회원/게시글 복합 PK. 단순 토글 대신 active=true/false로 의도를 전송. 중복 등록·반복 해제 시 상태 유지 |
| 동시성 | 부모 게시글 잠금 후 검증·관계 변경. 댓글 작업도 글→댓글 순서로 처리. 데이터 변경과 관리 기록은 같은 트랜잭션 |
| 집계 | 좋아요 관계를 원본으로 집계. 관계 JOIN으로 개수가 곱해지는 문제와 게시글마다 별도 왕복하는 N+1 방지 |
| 조회 비용 | 목록·고정 공지에서는 본문을 반환하지 않음. 관계별 회원·게시글 조회 인덱스와 LIMIT/OFFSET 사용 |
| 권한·개인정보 | 세션의 loginUser로 회원 식별. 내 목록의 회원 ID를 요청에서 받지 않음. 관리자·작성자 규칙 서버 검사 |
| CSRF·XSS·SQL | 기존 토큰 필터·ET.post·JSP 이스케이프 재사용. 동적 컬럼·정렬·관계명 허용 목록, 값은 PreparedStatement 바인딩 |
| 오류 복구 | 반응 저장 중 버튼 잠금, 서버 응답 형식 확인 후 상태 반영, 실패 시 선택 상태 유지·재시도 안내·버튼 복구. 작성·수정 검증 실패 시 입력 보존 |
| 접근성·화면 | 기존 Bootstrap 반응형 구성, 버튼·입력 label, 반응 aria-pressed, 상태 안내 aria-live, 키보드로 기본 조작 가능 |
| 추적 | 게시판 요청별 X-Request-ID, 처리 상태·소요 시간 로그. 본문·비밀번호·CSRF 토큰은 로그에 넣지 않음. 관리자 조치는 DB에 기록 |
| 시간 | 공지 DATETIME 입력은 한국 시간. DB 세션이 UTC여도 한국 시각을 명시해 기간 비교 |

길이 제한은 서버 Java String.length 기준으로 제목 200, 본문 10,000, 댓글 2,000, 신고·관리 사유 500이다. 조회수는 기존 세션별 최초 상세 조회 증가 규칙을 유지한다.

## 검증 방법

기본 테스트:

```powershell
.\mvnw.cmd test
node --test src/test/js/board.test.cjs
```

새 MySQL 통합 테스트는 임의 이름 `enjoytrip_board_test_<UUID>` DB를 생성하고 종료 시 해당 DB만 삭제한다. MySQL 네트워크 연결이 불가능하면 이 테스트는 건너뛰며, 실제 SQL·권한·제약 오류를 연결 불가로 숨기지 않는다. 테스트 계정에는 임시 DB 생성·삭제 권한이 필요하다.

전체 HTTP·부하 검증:

```powershell
.\mvnw.cmd clean package -DskipTests
.\mvnw.cmd test -Dboard.http=true -Dboard.tomcat=C:/SSAFY/apache-tomcat-11.0.27 -Dboard.load=true
node --test src/test/js/board.test.cjs
```

HTTP 검증은 **먼저 빌드한 WAR**를 임시 Tomcat의 임의 포트에서 실행한다. `board.tomcat`은 로컬 Tomcat 11 설치 경로다. `enjoytrip_board_http_<UUID>` DB를 사용하고 종료 후 테스트 서버와 DB를 정리한다. 로그 경로는 테스트 출력에 남긴다. 기존 실행 서버(8090)와 실제 서비스 DB를 새 게시판 HTTP 테스트 대상으로 사용하지 않는다.

## 확인한 사례

- 기존 21개 테스트 회귀, 신규 MySQL 기능·권한·동시성·삭제·기간·검색·페이지·쿼리 수 검증.
- 익명 조회, 공지 작성 권한, 타인 수정 차단, CSRF 누락 거부, 익명 AJAX 401, 숨김 글 404.
- 구형 공지 URL의 관리자 기본 유형·비관리자 403과 잘못된 유형 404 유지.
- 잘못된 수정 ID 400, 존재하지 않는 글 404가 예외 처리 중 500으로 변하지 않음.
- 실제 JSP 목록·폼·상세·신고 관리 렌더링, 본문 이스케이프, 검색 조건·댓글 페이지 유지.
- 반응 버튼의 저장 중 잠금, 성공 상태 반영, 통신 실패 후 같은 의도 재시도, 비정상 응답에 의한 상태 손상 방지.
- 독립 코드 검토에서 발견한 공지 시간대·기존 URL·수정 오류 처리·관리자 댓글 페이지 문제를 재현 테스트로 보완.

로컬 표본 부하: 게시글 10,000건, 동시 독자 8개, 최신/조회/좋아요 정렬 32회에서 서비스 계층 응답 p95 약 224ms를 측정했다. 네트워크·브라우저 시간을 포함하지 않으며, 10만 건·동시 사용자 50명 또는 운영 환경의 SLA를 검증한 결과는 아니다.

접근성은 기본 시맨틱·키보드 조작 구조를 적용했으며 스크린리더 전용 도구나 모든 브라우저·모바일 기기의 수동 인증까지 수행한 것은 아니다. 모든 오류 가능성이 없음을 보장하지 않고, 위 검증 범위로 호환성을 확인한다.

## 최종 실행 결과

- `mvnw.cmd clean package -DskipTests`: 성공.
- `mvnw.cmd test -Dboard.http=true -Dboard.load=true`: **51개 통과**, 실패 0, 오류 0, 건너뜀 0. 기존 21 + 신규 MySQL 23(부하 1 포함) + Tomcat HTTP 7.
- `node --test src/test/js/board.test.cjs`: **3개 통과**.
- 새 문서 링크 검사 정상. 원본 사본 비교에서 변경은 게시판·공통 메뉴·마이페이지 진입 링크·스키마 등록·문서에 한정. pom.xml 변경 없음.
- 기존 뉴스 XXE 차단 테스트가 출력하는 DOCTYPE 거부 문구는 기대한 방어 동작이며 테스트 실패가 아니다.
- 최초 커밋이 없는 저장소이므로 사용자 기존 파일을 일괄 스테이징·커밋하지 않았다. 현재 작업 브랜치는 codex/board-community이며 변경은 미커밋 상태다.

## 게시판 샘플 데이터

`src/main/resources/data/board-samples.csv`에 일반 게시글 15건을 포함한다. 앱이 시작될 때 최초 초기화에서 게시판이 비어 있으면 CSV를 읽어 저장하며, 이미 게시글이 있다면 기존 데이터를 유지하고 샘플을 추가하지 않는다. 초기화 여부를 DB에 기록하여 이후 글을 전부 삭제해도 재시작 시 샘플이 다시 생기지 않는다. 샘플 작성자는 로그인할 수 없는 전용 계정이다. 각 컴퓨터의 로컬 DB에 초기 데이터가 복사되는 방식이므로 이후 변경은 다른 컴퓨터와 동기화되지 않는다. CSV 수정은 최초 초기화가 끝난 DB에 자동 반영되지 않는다.

## 현실적인 샘플 보강

`board-sample-details.csv`와 `board-sample-comments.csv`에 작성자 15명, 2026-10-12~26 작성일, 조회수 46~391, 좋아요 1~12개, 내용별 댓글 32개를 관리한다. 모두 가상 여행 기록이다. 최초 보강 때 기존 v1 샘플 전용 계정의 원본 제목·본문이 그대로인 글만 매칭하여 갱신한다. 일반 회원 게시글과 편집된 샘플은 건드리지 않는다. 보강은 `board-samples-details-v2` 기록으로 한 번만 실행하며 이후 재시작 때 댓글·좋아요를 중복 생성하지 않는다. 샘플 회원은 로그인할 수 없는 전용 계정이다. 각 컴퓨터의 로컬 DB로 복사되며 이후 변경은 동기화하지 않는다.
