# 통합 게시판 확장 설계

사용자가 2026-10-30 승인한 범위: 기존 제안의 높음·보통 기능 전부와 공지 고정 관리. 기존 프로젝트 호환성이 최우선이다. 이미지 첨부·알림은 제외한다.

## 방식과 선택 근거

Servlet/JSP/JDBC를 유지하고 boards는 그대로 둔다. 확장 정보는 1:1 board_settings와 관계 테이블로 추가한다. 기존 컬럼을 ALTER하는 방식보다 기존 데이터와 초기화의 호환성을 확보하기 쉽다. Spring 전환은 범위에 없으며 공지 데이터를 일반 글로 변환하지 않는다. 메뉴와 목록을 통합하고 공지 유형·관리자 권한은 유지한다. 기존 type=notice/free 링크도 같은 목록의 필터로 수용한다.

## 동작

- 통합 목록: 전체/공지/일반 필터, 여행 후기·충전 팁·질문·동행 모집·일반 분류, 최신·조회·좋아요 정렬, 검색·페이징. 상세·작성·수정 왕복 시 조건 유지.
- 좋아요와 북마크: 로그인 회원, 글당 1건, 자기 글 허용, 공지에도 적용. 등록/해제 의도를 명시하고 반복 요청에 같은 상태 유지. 북마크는 비공개.
- 댓글: 로그인 작성, 본인 또는 관리자 수정·삭제. 1~2,000자, 페이지당 20건.
- 내 활동: 내가 쓴 글·댓글·좋아요한 글·북마크. 서버 세션 회원만 조회하며 페이지당 10건.
- 신고: 글/댓글, 이유 1~500자, 회원당 대상당 1건. 관리자 목록에서 확인하고 처리 사유를 남김.
- 숨김: 관리자만 글/댓글 숨김·복구, 사유 1~500자 필수, 감사 기록. 숨긴 글은 일반 조회·검색·반응·내 활동에서 제외하고 관리자만 조회. 숨긴 댓글은 일반 목록에서 제외.
- 공지 고정: 관리자만 설정, 순서 0~999, 선택적 시작/종료 시각(한국 시간). 시작 포함·종료 미포함. 첫 페이지의 전체 목록에서만 활성 공지를 상단에 별도 노출; 본문 목록과 중복시키지 않음. 검색·분류·내 활동에서는 별도 고정 노출 없음.
- 삭제: 기존 물리 삭제 유지. 신규 관계는 FK CASCADE. 탈퇴한 작성자의 글과 그에 연결된 타 회원의 저장 기록도 삭제되는 기존 정책을 문서화.

## 정합성·보안·호환성

DB 유일성으로 중복 방지. 변경 시 부모 게시글을 먼저 잠그고 권한·숨김·존재 여부를 확인한다. 댓글과 글을 함께 다루는 경우 글→댓글 순서로 잠근다. 집계는 관계 테이블 원본에서 조회하며 JOIN 행 곱셈과 N+1을 피한다. 로그인 ID는 세션에서만 받는다. CSRF·출력 이스케이프·PreparedStatement·허용 목록을 사용한다. 사용자 입력 URL로 리다이렉트하지 않고 검증한 목록 조건으로 복귀 주소를 만든다.

모든 신규 테이블은 CREATE IF NOT EXISTS, 초기화 순서에 등록한다. 기존 boards 행에 설정 행이 없어도 LEFT JOIN 기본값으로 조회한다. 성능은 쿼리 구조와 실측 결과를 기록하되 기존 제안의 부하 수치를 검증 없이 보장하지 않는다.

## 검증

기존 21개 테스트 회귀, 실제 MySQL의 격리된 테스트 스키마에서 CRUD·중복/동시 요청·권한·숨김·신고·기간·삭제 정리·구형 데이터 조회를 검사한다. WAR 빌드와 Tomcat JSP 렌더링·HTTP 요청에서 메뉴 통합·검색 상태·CSRF·에러 처리를 확인한다. 기존 실사용 DB에 검증용 글을 생성하지 않는다.
